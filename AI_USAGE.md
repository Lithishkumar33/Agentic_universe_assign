# AI Usage Disclosure

## Tools used
- Antigravity (Advanced Agentic Assistant / Gemini 3.8 Flash)

## What I used them for
- Scaffolding the initial project architecture (`solution/` package structure, database DDL schema).
- Generating parameterized regex patterns and test cases for messy Indian phone formats, multilingual/prefixed currency strings, and day-first date variations.
- Generating the test boilerplate across `pytest` test suites.

## What I wrote or decided myself
- **Database & Ledger Model**: Choosing SQLite in Write-Ahead Logging (`WAL`) mode with explicit transactions for zero external service dependencies while achieving sub-2-second runtime.
- **Blind Index for PII Protection**: Formulating the HMAC-SHA256 deterministic hash on canonical phone numbers (`+91XXXXXXXXXX`) to enable database joins and event linking without storing or exposing plaintext PII.
- **Two-Pass Reconciliation Engine**: Designing the orphan linking algorithm that links early-arriving events to newly ingested leads, and subsequently links supervisor overrides (`disposition.override`) to leads via `call_id`.
- **Precedence Hierarchy**: Structuring the strict order of lead row rejections (`schema order walk`) and bucket assignment logic (`yet_to_reach_out` -> `completed` -> `in_progress_telephony_failed` -> `in_progress_dialed`).
- **Idempotency Strategy**: Guaranteeing that re-running drops does not mutate database state or double-count metrics.

## Where the AI was wrong or unhelpful
- **Pytest 9.2.0 compatibility bug on Python 3.10**: An initial run failed with an internal error in pytest 9.2.0 (`AttributeError: 'NodeId' object has no attribute '_str_cache'`). I diagnosed this as an upstream incompatibility in the newly released pytest 9.2.0 on Python 3.10 and pinned `pytest>=8.0,<9.0` in `requirements.txt`.
- **Blank Row Handling**: The initial drafted CSV parser counted blank lines toward `lead_rows_total` and incremented the 1-based row counter. Cross-referencing line 90 of the specification ("Blank rows (every cell empty or whitespace) are skipped and not counted") revealed this would corrupt rejection row numbers, so I adjusted the parser to discard blank rows prior to incrementing counters.
- **Override Phone Absence**: An early prototype assumed all events had a `phone` attribute. Reviewing `generate_data.py` and the spec revealed `disposition.override` has no `phone` field, requiring `call_id`-based foreign key resolution.

## How I verified AI-generated code
- Automated test suite: Developed 28 unit and integration tests covering phone normalisation, date parsing, decimal parsing, header mapping, effective disposition, bucket derivation, and idempotency.
- Byte-for-byte diffing: Verified that running `ingest data/drop_1` followed by `ingest data/drop_2` produces identical CSV and JSON reports to ingesting all batches simultaneously.
- End-to-end verification against the synthetic dataset generated by `generate_data.py`.
